# BOZKURT PANEL v1.2.0 — 2026-10-11

**16 one-click applications, no "coming soon" anywhere, a polished UI.** Free (Apache-2.0) web
hosting control panel with a cPanel/WHM-style layout and the same ports (2083 user, 2087 admin,
2096 webmail) for **Ubuntu 24.04 LTS** and **AlmaLinux 9**. 100 % free software: no paid component,
licence or API.

### App Installer — 16 free applications
WordPress · Joomla! · Drupal · Nextcloud · Matomo · phpBB · MediaWiki · DokuWiki · Grav (+Admin) ·
Backdrop CMS · WonderCMS · MyBB · OpenCart · Mautic · Omeka S · FOSSBilling.

Every archive is pinned to the SHA-256 its project publishes (or verified against the upstream GPG
signature first) and extracted with strict containment rules (tar **and zip**: no absolute or `..`
names, no links or device files, size and entry limits). The installer page has search, categories,
EN/TR descriptions, PHP/database badges, an "Installed" badge and a credentials box after install.

### Also new
- **Change Primary Domain** (WHM › Modify Account): an addon domain becomes the primary domain and
  the old primary an addon domain, in one transaction; sites, DNS, mail and SSL keep working.
  Billing/webhook event `account.primary_domain_changed`.
- `make release-unsigned` builds the unsigned tarballs + `.sha256` used by the GitHub releases.

### Fixed
- Nextcloud could not be installed (121 relative symlinks in its tarball; same-archive file links
  are now written as copies, every other link is still refused).
- Mailbox logins / password changes could lag behind Dovecot's per-second passwd-file cache.
- BPanel Shield showed "COMMAND UNAVAILABLE" as the ClamAV 1.5 version next to "OK".
- The user dashboard's empty "Planned tools (0)" box and the whole "coming soon" machinery removed;
  26 pages used CSS classes no stylesheet defined (cards, tabs, badges) — now shared utilities.

## Install / upgrade

> **The archives are not signed** (no release key yet): check the SHA-256. Tested in an Ubuntu 24.04
> container with systemd and the real services, **not yet on a real VPS or on AlmaLinux 9** — use a
> disposable server first.

```sh
V=1.2.0; A=amd64   # A=arm64 on ARM servers
curl -fLO https://github.com/cumabozkurt/bpanel/releases/download/v$V/bpanel-$V-linux-$A.tar.gz
curl -fLO https://github.com/cumabozkurt/bpanel/releases/download/v$V/bpanel-$V-linux-$A.tar.gz.sha256
sha256sum -c bpanel-$V-linux-$A.tar.gz.sha256
tar -xzf bpanel-$V-linux-$A.tar.gz && cd bpanel-$V-linux-$A
sudo BPANEL_ALLOW_UNSIGNED=1 ./install.sh --hostname panel.example.com --email admin@example.com --profile full --yes
# existing v1.x server:
sudo BPANEL_ALLOW_UNSIGNED=1 ./install.sh upgrade --yes
```

## Known limitations
- Not yet run on a real VPS or AlmaLinux 9; SFTP/S3 backup targets, Let's Encrypt production, the real
  Cloudflare API and multi-server across two hosts were not exercised.
- Unsigned archives; `curl | bash` stays closed until a release key exists.
- The App Installer downloads and unpacks the application and creates its database; the
  application's own web setup (admin account, site name) is finished in the browser, as with
  Softaculous' "manual" mode.
